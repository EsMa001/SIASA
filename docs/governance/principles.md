# Prinzipien

Importierte Governance- und Ethikprinzipien. Quelle: `stakeholder_requirements_information_space_mvp_v0_4 (1).xlsx` / Sheet `Principles`.

| ID | Kategorie | Prinzip | Bedeutung |
| --- | --- | --- | --- |
| DG-001 | Daten-Governance | Zweckbindung | Daten nur für definierte Analyseziele nutzen. |
| DG-002 | Daten-Governance | Datenminimierung | Nur speichern, was nötig ist. |
| DG-003 | Daten-Governance | Quellenkonformität | Nutzungsbedingungen und Lizenzen beachten. |
| DG-004 | Daten-Governance | Rollen-/Akteurskontext | Personen nur im öffentlichen/institutionellen Kontext. |
| DG-005 | Daten-Governance | Kein Targeting | Keine Zielgruppen- oder Personenansprache. |
| DG-006 | Daten-Governance | Kein Doxing | Keine Deanonymisierung, Lokalisierung oder Kontaktinfos. |
| DG-007 | Daten-Governance | Keine Risikoetikettierung von Personen | Risiko nur auf Länder-/Domänen-/Signalebene. |
| DG-008 | Daten-Governance | Transparenz | Quelle, Kontext und Unsicherheit dokumentieren. |
| DG-009 | Daten-Governance | Löschbarkeit | Personenbezogene Daten entfernbar halten. |
| DG-010 | Daten-Governance | Exportkontrolle | Personenbezogene Inhalte in Reports begrenzen. |
| EP-001 | Ethik | Analyse statt Operation | Beobachtung und Strukturierung, nicht operative Handlung. |
| EP-002 | Ethik | Evidenz vor Interpretation | Schlussfolgerungen müssen auf nachvollziehbarer Evidenz beruhen. |
| EP-003 | Ethik | Unsicherheit sichtbar machen | Unsicherheit ist ein Kernergebnis. |
| EP-004 | Ethik | Keine Zielobjekte | Personen, Gruppen oder Infrastrukturen werden nicht als Ziele bewertet. |
| EP-005 | Ethik | Keine manipulative Nutzung | Keine Unterstützung von Propaganda, Desinformation oder Targeting. |
| EP-006 | Ethik | Quellenkritik | Quellenabhängigkeit, Bias und Replikation werden explizit modelliert. |
| EP-007 | Ethik | Datenminimierung | Nur speichern, was für Analyse erforderlich ist. |
| EP-008 | Ethik | Review vor Öffentlichkeit | Veröffentlichbare Reports sollen geprüft werden. |
| EP-009 | Ethik | Attribution mit Vorsicht | Cyber-, InfoOps- und Konfliktzuschreibungen benötigen Evidenz und Unsicherheitsangabe. |
| EP-010 | Ethik | Keine Scheingenauigkeit | Keine numerische/farbige Darstellung ohne Kontext. |
| OP-001 | Betrieb | Local-first MVP | Der erste MVP soll lokal betreibbar sein. |
| OP-002 | Betrieb | Container-ready | Docker/Container-Betrieb vorbereiten. |
| OP-003 | Betrieb | No silent failures | Fehler müssen sichtbar und protokolliert sein. |
| OP-004 | Betrieb | Partial success allowed | Teilweise erfolgreiche Runs zulässig, aber klar kennzeichnen. |
| OP-005 | Betrieb | Backfill ≠ Daily Run | Historische Backfills und tägliche Updates trennen. |
| OP-006 | Betrieb | Config over hardcoding | Länder, Quellen, Features und Regeln konfigurierbar halten. |
| OP-007 | Betrieb | Secrets outside code | Zugangsdaten dürfen nicht im Code liegen. |
| OP-008 | Betrieb | Reversible operation | Backups und Reprocessing sollen Datenverlust vermeiden. |
| TR-001 | Traceability | Stable IDs | IDs bleiben stabil und werden nicht wiederverwendet. |
| TR-002 | Traceability | Evidence chain | Jede Aussage muss bis zur Quelle rückverfolgbar sein. |
| TR-003 | Traceability | Version everything | Regeln, Features, Quellen, Länder und Reports werden versioniert. |
| TR-004 | Traceability | No silent overwrite | Reprocessing überschreibt keine alten Ergebnisse. |
| TR-005 | Traceability | Explain status changes | Statusänderungen müssen erklärbar sein. |
| TR-006 | Traceability | Reports are snapshots | Reports sind an konkrete Snapshots gebunden. |
