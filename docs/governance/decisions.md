# Projektentscheidungen

Beschlossene Festlegungen aus der Stakeholder-Arbeitsmappe. Quelle: `stakeholder_requirements_information_space_mvp_v0_4 (1).xlsx` / Sheet `Decisions`.

| ID | Bereich | Festlegung | Status |
| --- | --- | --- | --- |
| D-001 | Projektziel | Strukturelle Analyse globaler Informations- und Aktivitätsräume unter Unsicherheit. | beschlossen |
| D-002 | Analysefokus | Länderzentriert, nicht situations-/krisenfokussiert. | beschlossen |
| D-003 | Domänen | A Informationsraum, B Ereignisdaten, C physische Aktivität, D Wirtschaft/Struktur, E Cyber/Tech/InfoOps. | beschlossen |
| D-004 | Narrative | Narrative sind Teilkomponente von Ebene A, nicht alleiniger Systemfokus. | beschlossen |
| D-005 | Fusion | Kein allgemeiner numerischer Gesamt-Score im MVP; keine naive additive Fusion. | beschlossen |
| D-006 | Statuslogik | D0–D5 je Domäne; S0–S6 regelbasierter Multi-Domain-Status. | beschlossen |
| D-007 | Weltkarte Default | Startseite = Weltkarte; Default = Multi-Domain-Status, 7 Tage, relative Baseline, kombinierte 30/90/365-Baseline. | beschlossen |
| D-008 | Vergleichsmodus | Relative Baseline als Default; globaler Vergleich als Umschalter. | beschlossen |
| D-009 | Historie | Initial mindestens 3 Jahre historische Daten, soweit Quellen verfügbar. | beschlossen |
| D-010 | Betrieb | Nach Initialaufbau tägliche inkrementelle Runs mit versionierten Snapshots. | beschlossen |
| D-011 | Länderset | MVP mit 30 Ländern; Hybrid ca. 70 % Fokus, 30 % Kontroll-/Referenzländer. | beschlossen |

| D-013 | MVP-Core-Domänen | A/B/D verpflichtender Kern; C/E selektiv, wenn Datenlage reicht. | beschlossen |
| D-014 | ACLED | Prepared Adapter; wegen fehlendem Zugriff keine MVP-Abhängigkeit. | beschlossen |
| D-015 | Annotationen | Regelbasierte Statuswerte; Analysten-Annotationen ergänzend, nicht überschreibend. | beschlossen |
| D-016 | Review | Kein formaler Review-Workflow im MVP; Datenmodell bereitet Review-Status vor. | beschlossen |
| D-017 | Reporting | Daily Global Snapshot automatisch nach Run; Detailreports manuell aus GUI. | beschlossen |
| D-018 | Rollen | MVP mit Admin/Developer + Analyst; Viewer optional vorbereitet; kein Public User. | beschlossen |
| D-019 | Nutzerrollen | MVP mit Admin/Developer und Analyst; Viewer optional vorbereitet; Public User nicht im MVP. | beschlossen |
| D-020 | Haupt-Use-Cases | UC-001 Daily Global Review, UC-002 Country Deep Dive, UC-003 Source/Coverage Review und UC-004 Report Export sind MVP-Pflicht. | beschlossen |
| D-021 | Validierung | MVP mit 10–15 manuell kuratierten historischen Referenzfällen; einfacher Backtest, kein vollständiger Point-in-Time-Backtest. | beschlossen |
| D-022 | Qualität | Traceability, Reproduzierbarkeit, D0 statt Schätzung bei Datenlücken und No Silent Failure als harte Qualitätsprinzipien. | beschlossen |
| D-023 | Governance | Keine Volltextspeicherung geschützter News; Social Media restriktiv; personenbezogene Analyse nur für öffentliche/institutionelle Akteurskommunikation. | beschlossen |
| D-024 | Ethik | Keine Zielauswahl, keine operative Empfehlung, keine Desinformation, kein Targeting, keine ungeprüfte Veröffentlichung. | beschlossen |
| D-025 | Betrieb | Local-first MVP; tägliche Runs; Backfills; strukturierte Logs; Secrets außerhalb Code; Docker vorbereitet. | beschlossen |
| D-026 | Traceability | Stable IDs und Evidenzpfad Source → Raw → Normalized → Feature → Domain Status → Multi-Domain Status → Snapshot → Report. | beschlossen |
| D-027 | MVP-Priorisierung | MVP-Must/Should/Could/Post-MVP/Out-of-Scope-Klassen werden verwendet. | beschlossen |
